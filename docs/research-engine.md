# Research Engine v0.3

Центральный оркестратор управляет задачами проекта и использует существующие
плагины. Архитектура v0.1/v0.2 сохранена: команды scan/run и API Scheduler/Store
работают как прежде, а новая система хранит состояние в дополнительных таблицах.

## Быстрый запуск

Из корня установленного проекта, для разрешённого локального target:

```bash
research open KESL --root /srv/lab/kesl-source
research start --plan config/research-plan.yaml
research status
research progress
research timeline --limit 30
research checkpoints
research dashboard --engine --output Research-Engine.html
```

`start` работает в foreground и создаёт новое исследование. Без --plan используется
одна source-задача, workers/timeout/attempts берутся из старого config/example.yaml.
Внутри исследования этап analysis выполняет плагин; затем результаты проецируются
в знания и сохраняется итоговый отчёт. YAML DAG позволяет задать дополнительные этапы.
`start --prepare` только сохраняет план и начальный checkpoint.

Глобальные флаги --config, --workspace и --project ставятся перед командой.
Фоновый запуск через shell/systemd организуется оператором; скрытые фоновые
процессы или автозапуск новых исследований CLI не создаёт.

## Пауза, отмена и продолжение

Из второго терминала во время работы:

```bash
research stop                    # пауза всего исследования
research resume                  # продолжить последнее исследование
research resume --workers 4      # изменить размер пула при продолжении
research stop --task inventory   # окончательно отменить один узел по key/UUID
research stop --cancel           # окончательно отменить всё исследование
```

`--run UUID` выбирает конкретное исследование для stop/resume/progress/timeline/checkpoints.
По умолчанию выбирается последнее. В проекте допускается одно незавершённое
исследование (ready/running/paused). Новый start требует завершить либо отменить его.

Ctrl+C переводит текущий запуск в paused и выполняет cleanup. stop передаёт запрос
через SQLite; ответ команды показывает **текущее** состояние. Переход running → paused
происходит после обработки запроса supervisor и завершения worker-процессов.
Обычная пауза возвращает активные задачи в pending, не расходуя бюджет ошибок.
Завершённые задачи не запускаются повторно. Отмена одной задачи блокирует её
потомков, но не останавливает независимые ветви DAG.

После аварийного завершения supervisor используйте resume. Если run ещё помечен
running, общая OS-блокировка не позволит запустить второй живой supervisor.
После получения блокировки оборванные попытки учитываются как ошибки и возвращаются
в очередь, пока не исчерпан max_attempts. Задачи с исчерпанным бюджетом остаются failed;
resume не обнуляет этот бюджет. Для нового исследования после окончательной ошибки
можно выполнить start заново.

## План и зависимости

```yaml
name: Authorized source and behavior research
workers: 3
checkpoint_minutes: 5
tasks:
  - key: inventory
    stage: static-analysis
    plugin: source
    priority: 1
    timeout: 120
    attempts: 3
  - key: tests
    stage: behavior-analysis
    plugin: dynamic
    priority: 2
    depends_on: [inventory]
    timeout: 300
    attempts: 1
```

Плагины используют прежний Context и async run. Все задачи получают snapshot
настроек root/command/лимитов из runtime YAML и выбранного проекта. command запускается
только для dynamic; необходимо allow_dynamic=true и явный argv в runtime YAML.
Сам план не исполняет shell и не включает эксплойты или сетевое сканирование.

Приоритет 1 выше 2 и 3; он влияет на готовые задачи, не вытесняя уже запущенные.
Зависимость требует состояния completed. Ошибка, отмена либо blocked у родителя
переводит зависимые pending-задачи в blocked. Циклы, неизвестные ключи, пустые поля,
NaN/бесконечные интервалы и недоступные плагины отклоняются до создания run.
Повторы используют задержку 0.4, 0.8, 1.6… секунд, максимум 30 секунд.

## Worker Pool

Каждая попытка — отдельный процесс Python с одним плагином. Supervisor управляет
ими через asyncio; размер пула 1–32, изменяемый при resume. Это масштабирование
на одном узле; распределённого брокера/кластера в v0.3 нет.

Таймаут включает запуск процесса и выполнение плагина. На Linux отмена отправляет
SIGTERM группе процессов; через 2 секунды при необходимости используется SIGKILL.
Python worker обрабатывает SIGTERM через отмену async-задачи. При исчезновении
родителя Linux worker обнаруживает это отдельным потоком и завершает работу.
Плагины должны корректно обрабатывать CancelledError и освобождать внешние ресурсы.

Процессная изоляция не является security sandbox. Для контролируемых тестов
по-прежнему используйте VM/container. Демоны, отделившиеся в новую сессию, требуют
cgroup/VM cleanup. На Windows проверено завершение самого worker-процесса;
Linux — основная целевая ОС для lifecycle всей process group. Worker PID записывается
в timeline. Схема at-least-once допускает повтор целой задачи после аварии;
внешние побочные эффекты команды не откатываются.

## Checkpoints и восстановление

CheckpointManager сохраняет снимок ResearchRuns и ResearchTasks каждые
checkpoint_minutes, а также при создании, паузе и завершении. Изменения очереди,
результатов и событий сохраняются немедленно, поэтому recovery использует
последний checkpoint как recovery marker и продолжает с более новых committed
состояний. Это не восстановление Python heap и не продолжение с произвольной
инструкции внутри плагина: повторяется прерванная задача целиком.

На resume сохраняются completed, отменённые задачи и ручные решения исследователя.
Если сбой произошёл между сохранением результата и Knowledge ingest, доставляется
уже сохранённый результат. Ошибка проекции отмечает run как failed и допускает
повтор проекции через resume без повторного выполнения completed-задач.

Для автоматического возобновления после перезапуска сервиса используйте systemd
с `ExecStart=.../research --workspace ... --project KESL resume` и Restart=on-failure.
В production выбирайте KillMode=control-group для дополнительного cleanup потомков.
Сервис и права доступа не устанавливаются автоматически.

## Прогресс и timeline

progress возвращает total/completed/running/pending/failed/cancelled/blocked,
errors=failed+blocked, configured workers, active_workers, elapsed_seconds и
tasks_per_minute. Время считается только во время работы supervisor (включая ожидание
retry и cleanup), без пауз. Скорость — completed / активное время; это средняя,
а не моментальная скорость. supervisor_alive оценивается по heartbeat за последние
10 секунд; это индикатор свежести, а не доказательство существования процесса.

ResearchTimeline содержит created_at UTC epoch, event, task_id, duration и JSON
details. События task_started содержат key/stage/plugin/attempt/worker;
task_completed содержит job_id и artifact_id; ошибки — причину. Список выдаётся
от новых к старым; `timeline --before EVENT_ID --limit 100` листает историю.
Статус проекта v0.2 расширен полем research_engine; остальные поля сохранены.

## Артефакты и Knowledge Engine

ArtifactManager сохраняет SHA-256-вложения в существующем artifacts/:

- JSON результатов анализа;
- логи каждой попытки (до 64 KiB, остальной вывод дренируется без накопления);
- итоговый JSON-отчёт с задачами, timeline, метаданными проекта и снимком всех заметок;
- HTML Research Engine dashboard.

Одинаковые байты хранятся один раз; метаданные логов сохраняют связь с конкретной
попыткой. Идентификатор лога доступен в событии worker_log. В Artifacts.evidence
есть blob — относительный путь внутри каталога проекта.

ResultAggregator атомарно связывает completed-задачу с одной записью jobs,
затем использует существующий идемпотентный knowledge ingest. Во время долгих
исследований ingest выполняется примерно раз в 5 секунд и обязательно при остановке.
Кандидаты остаются кандидатами: подтверждение результата выполняется человеком.

Проектный ZIP v0.3 (manifest version=2) переносит engine-таблицы, события,
checkpoints, результаты и вложения. Импорт архивов v0.2 (version=1) поддержан.
Установка v0.2 не обязана читать архив будущего формата. После импорта явно укажите
root; import никогда не запускает сохранённые команды. Исследовательские scratch-файлы
engine-work не включаются в экспорт и могут остаться после аварии процесса.

## Ограничения и расширение

Максимум 10 000 задач на план, timeout до 7 дней, retries до 100. Результат worker
ограничен 128 MiB при приёме supervisor; trusted-плагин может до проверки записать
более крупный файл, поэтому для жёсткой дисковой квоты нужны настройки ОС.
Checkpoint/отчёт/архив загружают метаданные в память. Retention остаётся обязанностью
оператора; перед многочасовой эксплуатацией на больших графах нужны нагрузочные тесты.

Новые анализаторы подключаются прежними entry points research_platform.plugins.
Компоненты оркестрации разделены по файлам: manager, scheduler, pool, artifacts,
state, plan. Таблицы ResearchSchema/Runs/Tasks/Dependencies/Events/Checkpoints
добавляются рядом с существующими, PRAGMA user_version legacy-базы не меняется.
