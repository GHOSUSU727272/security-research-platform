# Project Knowledge System — проектирование v0.2

## Совместимость и границы

Модуль добавляется поверх v0.1. Store, Scheduler, Plugin и старые таблицы очереди
сохраняются. Без выбранного проекта старые команды работают как прежде;
`--legacy` явно включает этот режим даже при выбранном проекте.

## Изоляция

ProjectManager хранит небольшой SQLite-каталог workspace/catalog.sqlite3
(ID, имя, локальный root и активный проект). Для каждого UUID создаётся отдельный
каталог projects/UUID с собственной research.sqlite3, artifacts/ и журналом.
В этой базе живут старые таблицы jobs/reviews и новая память проекта. Имя проекта
никогда не используется как путь. Это логическая изоляция на одном узле, а не
граница доступа между недоверенными ОС-пользователями.

## Данные

Projects содержит единственную запись: UUID, имя, описание, продукт, версия,
created_at, last_researched_at, status. В остальных сущностях есть UUID,
project_id, название, состояние, приоритет, timestamps и JSON evidence.
Таблицы: Artifacts, Functions, Libraries, Modules, Findings, Hypotheses,
Experiments, InterestingLocations, FalsePositives, ResearchHistory, Notes,
Relationships. Общий реестр KnowledgeEntities позволяет ссылаться на любой
узел графа через настоящие FK, без невалидируемых polymorphic references.
Каждая предметная таблица имеет FK к этому реестру. Связи допускаются только
между узлами своей базы/проекта. Notes хранят category/body; связи с функциями
и библиотеками представлены рёбрами refers_to.

## Сервисы

KnowledgeEngine: добавление, поиск, смена состояний и сводка прогресса;
GraphEngine: типизированные связи и обход соседей; ProjectManager: создание,
выбор, перенос и локальная привязка root. Изменения фиксируются в ResearchHistory.
Состояния задаются отдельно для типов: функции/библиотеки unreviewed/reviewed;
гипотезы open/testing/confirmed/rejected; результаты candidate/confirmed/dismissed.
Прогресс — доля reviewed функций и библиотек, не оценка покрытия продукта.

## Интеграция запусков

CLI направляет существующий Store в базу выбранного проекта. После работы очереди
идемпотентный ingest связывает jobs с Experiments, импортирует статический индекс,
функции, библиотеки и находки и записывает историю. Повторный ingest не дублирует
узлы и не сбрасывает ручные статусы. AST-анализ дополнительно возвращает объявления
функций (включая функции без вызовов); формат v0.1 только расширяется.

## Перенос

Экспорт: ZIP с manifest.json, data.json (записи согласованного SQLite snapshot через
backup API) и копиями вложенных артефактов. JSON выбран для восстановления только
известной схемы без переноса чужих SQLite triggers/views. SHA-256 и размеры
проверяются при импорте. Импорт не извлекает произвольные
пути, не загружает плагины, не выполняет SQL из архива и не запускает команды.
Конфликты ID/имён отклоняются. Локальный root не переносится: после импорта его нужно
явно привязать. Экспорт включает память, очередь и вложения, но не весь внешний
исследуемый продукт. История старых путей сохраняется как evidence.

## UI и проверки

Статический HTML dashboard с экранированием пользовательских полей, метриками,
очередью ручной проверки и последними запусками; доступен без сервера и JS.
Тесты: изоляция двух проектов, FK графа, состояния, заметки, ingest/re-ingest,
round-trip архива с вложениями, повреждение/опасные архивы, старый CLI и новый CLI.
