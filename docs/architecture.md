# Архитектура и этапы

Платформа локального анализа авторизованных проектов. Находки — эвристические
сигналы для ручной проверки, а не доказательства уязвимостей.

1. Ядро: типизированные контракты, YAML, SQLite WAL, очередь с lease и heartbeat.
2. Индексация и AST: потоковый обход, ограничение размера файлов, Python call graph,
   инвентаризация манифестов, чувствительные вызовы.
3. Динамика: opt-in команды без shell, таймаут, ограниченные логи, сравнение запусков.
4. Аналитика, память, экспорт и тесты.

Зависимости направлены к core/models.py. Plugins реализуют единый async-контракт;
планировщик не знает деталей анализа. SQLite хранит очередь, историю, результаты,
комментарии и связи. Каждая задача атомарно сохраняет результат и завершение.
Истёкшие lease восстанавливаются после перезапуска. Повторные попытки ограничены.
Доставка at-least-once: плагины должны быть идемпотентны; внешние эффекты команды
не могут быть откатаны SQLite. Один процесс-планировщик на базу; workers async.

Динамическая команда исполняет произвольный локальный код. Это не sandbox:
используйте отдельную VM/container без секретов и с ограниченной сетью.
Сетевого сканирования и автоматической эксплуатации нет.

Границы MVP: AST-граф синтаксический, не разрешает polymorphism/alias/import dispatch;
анализ зависимостей инвентаризирует манифесты, не сверяет CVE. SQLite подходит для
одного узла. Enterprise production требует нагрузочной проверки, модели доступа,
политики retention/backup и deployment-specific isolation.
