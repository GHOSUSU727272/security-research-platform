# Research Engine v0.3 — архитектура до реализации

## Место в существующей системе

Новый пакет core/research оркестрирует существующие Plugin/Context и использует
проектную SQLite. Scheduler v0.1 и его команды scan/run остаются отдельным API.
Общая блокировка scheduler.lock исключает одновременную запись результатов двумя
исполнителями. KnowledgeEngine, граф, заметки и проектный архив сохраняются.

## Компоненты

- ResearchManager: создание исследования из YAML DAG, запуск/возобновление,
  согласованное завершение и остановка.
- TaskScheduler: приоритетная очередь готовых узлов DAG, retries с задержкой,
  propagation ошибок/отмены на зависимые задачи. Циклы отклоняются до записи.
- WorkerPool: N независимых процессов Python, по одному процессу на активную
  задачу; асинхронный supervisor управляет процессами и таймаутами. Масштабирование
  локальное через workers, без распределённой инфраструктуры.
- ArtifactManager: неизменяемые content-addressed вложения через схему Artifacts;
  результаты, логи попыток и итоговый отчёт со снимком заметок/метаданных.
- ProgressTracker: SQL-счётчики состояний, активное время, скорость успешных задач.
- CheckpointManager: каждые N минут атомарный снимок состояния в SQLite,
  плюс контрольные точки при stop/finalize. Каждое изменение задачи сохраняется
  немедленно; recovery не откатывает уже завершённые задачи к старому checkpoint.
- ResultAggregator: атомарная публикация успешного результата в jobs v0.1,
  идемпотентный knowledge ingest v0.2 и создание артефактов.
- ResearchTimeline: датированные события с задачей, этапом, длительностью,
  результатом и ошибкой; входит в экспорт проекта.

## Хранение и состояния

Аддитивные таблицы ResearchRuns, ResearchTasks, ResearchDependencies,
ResearchEvents, ResearchCheckpoints. Отдельная версия схемы, без изменения jobs.
Run: ready/running/paused/completed/failed/cancelled. Task:
pending/running/completed/failed/cancelled/blocked. Dependencies требуют completed.
Приоритет 1 — самый высокий; равные приоритеты упорядочиваются детерминированно.

stop без task переводит run в paused и отменяет активные попытки с cleanup;
они возвращаются в pending для resume. stop --task отменяет одну задачу окончательно,
её потомки становятся blocked. stop --cancel отменяет всё исследование окончательно.
Повторы после таймаута/ошибки ограничены max_attempts; ручная пауза не расходует
бюджет ошибок. После аварии running-задачи возвращаются в очередь (at-least-once),
успешные результаты не исполняются повторно. Эффекты динамических команд не откатываются.

## Восстановление и перенос

Периодический checkpoint хранит состояние задач и активное время; timeline и
очередь транзакционно актуальнее последнего снимка. После resume manager восстанавливает
оборванные попытки и продолжает DAG. Повторяются целые задачи, а не инструкции
внутри стороннего плагина. Supervisor heartbeat позволяет отличить живой процесс
от stale running в status; ОС-блокировка остаётся источником права на execution.

Архив v0.3 включает новые таблицы; импорт v0.2 поддерживается и добавляет пустую
схему engine. v0.2 не обязан понимать архивы будущего формата. Локальный root
перепривязывается явно, импорт ничего не исполняет.

## CLI и отчёты

start [--plan YAML], resume [--run UUID], stop [--run UUID] [--task ID|--cancel],
progress, timeline, checkpoints. start/resume работают в foreground; stop можно
вызвать из другого терминала. Статус проекта расширяется полем research_engine,
старые поля сохраняются. dashboard --engine создаёт отдельную офлайн HTML-страницу.

## Проверки

DAG/приоритеты, независимость worker'ов, hard timeout, retry, зависимости после
ошибки, пауза/отмена, crash recovery, периодические checkpoints, отсутствие дублей,
изоляция проектов, импорт v0.2/round-trip v0.3, CLI и экранирование dashboard.
Linux runtime и многочасовые soak-тесты отмечаются отдельно от локальных тестов.
