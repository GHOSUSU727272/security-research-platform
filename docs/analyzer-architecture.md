# Рабочие анализаторы — расширение v0.3

Сохраняются Plugin.run(Context), очередь, проекты, Knowledge Engine и Research
Engine. В Context добавляются только необязательные поля plugin_options,
checkpoint_db и task_id; старые сериализованные задачи продолжают загружаться.
YAML plugin_options содержит отдельные настройки каждого зарегистрированного имени.

FileAnalyzer — общий механизм обхода без перехода по симлинкам, фильтров файлов,
пофайловых SHA-256 checkpoints, статистики и логирования. Каждый анализатор
работает самостоятельно и не требует предварительного запуска другого плагина.
Checkpoint сохраняется только после успешного разбора файла; ошибка не кешируется.
Возобновление проверяет содержимое файла, версию анализатора и параметры.
SQLite-таблицы PluginFileCache/PluginProgress дополняют проектную базу и архив;
В v0.4.1 worker'ы передают операции через CheckpointClient в ограниченную очередь
supervisor; единственный writer подтверждает каждую запись после commit.
Endpoint и токен создаются на время попытки, не сохраняются в проектных задачах.
Standalone запуск сохраняет локальный backend. Детали: [SQLite writer](sqlite-writer.md).

ELF/Imports используют pyelftools. Callgraph/CFG используют Capstone для ELF x86,
x86-64, AArch64 и Python AST там, где поддерживается. Неизвестные indirect edges
сохраняются как unresolved; полнота графа не обещается. Ghidra — отдельный headless
backend с поставляемым Java postScript через официальный analyzeHeadless.
Memory — только явно разрешённый PID и чтение диагностических /proc файлов;
нет /proc/PID/mem, ptrace, дампа адресного пространства или повышения привилегий.

Результаты содержат records, статистику, файлы и стабильные сущности/связи.
Аддитивный knowledge adapter переносит предметные записи в память и связывает
наблюдения нескольких плагинов через SHA-256 одного артефакта. Графы дополнительно
публикуются в JSON и экранированном HTML через Artifact Manager.

План KESL запускает независимые анализаторы параллельно существующим WorkerPool.
TaskSpec.options аддитивно задаёт настройки отдельной задачи поверх Context;
подготовщик KESL использует точные files для распределения отдельных файлов.
Archive v3 переносит новые таблицы; читатель сохраняет поддержку v1/v2.
Memory/Ghidra включаются только с явными параметрами; отсутствие backend — явная
ошибка конфигурации, а не успешный пустой результат. Для реального KESL пути
и PID обнаружены в VM, выполнен сквозной тест на выборке, полный план подготовлен.
Подробности фактической проверки и ограничений — в validation.md.
